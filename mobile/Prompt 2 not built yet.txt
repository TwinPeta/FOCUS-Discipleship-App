### Prompt 2 — Detailed Screen Breakdown (What It Does & What It Connects To)

30. Manage community (super-mentors) — `/community/:id/manage`
  • What it does:
    - Super-mentor dashboard ("Only super-mentors see this.") displaying 4 tappable summary cards with live counters:
      1. Join requests ("Approve or decline students")
      2. Reports to review ("Level 1 moderation")
      3. Members to follow up ("No activity for 14+ days" — lists inactive members with a direct Message button per row, computed from activity events)
      4. Meeting details ("Tuesday · 5:00 PM · {room}")
    - Shows footer note: "Cover photos and community creation are managed by the admin team."
  • What it connects to:
    - Incoming navigation: `CommunityShell` header "Manage" action button on `/community/:id/feed` (visible only when `currentRoleProvider == UserRole.superMentor`).
    - Outgoing navigation:
      • Card 1 -> Screen 31 (`/community/:id/manage/requests`)
      • Card 2 -> Screen 32 (`/community/:id/manage/reports`)
      • Card 3 "Message" button -> Screen 10 (`/messages/:threadId` via `ThreadRepository`)
    - Guards & Repositories: Protected by `MembershipGuard` (requires approved membership in `:id` + `UserRole.superMentor`); reads from `CommunityRepository`, `JoinRequestRepository` (`pendingJoinRequestsProvider`), `ReportRepository` / `ModerationRepository`, `ActivityRepository`, and `MessagingRepository`.

31. Join requests — `/community/:id/manage/requests` [Already Built in `join_requests_screen.dart`]
  • What it does:
    - Lists pending student join requests for the community ("A student can be in only one specific community.").
    - Each card displays student initials avatar, full name, `@username · {institution}`, relative request date, amber "Approve" button, and outlined "Decline" button.
    - If the student is already in another specific community (`existingCommunityName != null`), displays "Already in {community}" and disables "Approve".
    - "Approve" transitions request to `approved` and notifies the student; "Decline" opens `showTextInputDialog` for an optional message, sets status to `declined`, and notifies the student.
  • What it connects to:
    - Incoming navigation: Screen 30 (`/community/:id/manage`) Join requests card.
    - Outgoing side-effects & triggers: Emits `NotificationType.requestApproved` (target `/request/approved`, Screen 27) or `NotificationType.requestDeclined` (target `/request/declined`, Screen 28) via `NotificationRepository`.
    - Guards & Repositories: `MembershipGuard` (`UserRole.superMentor`), `JoinRequestRepository` (`joinRequestRepositoryProvider`, `pendingJoinRequestsProvider`), `NotificationRepository` (`notificationsProvider`), `ConnectivityService` (`isOnlineProvider` + `OfflineBanner`).

32. Reports to review (Hide / Warn / Keep / Escalate) — `/community/:id/manage/reports` (under manage)
  • What it does:
    - Level 1 moderation queue for super-mentors ("You can hide content and warn members. Admins handle suspensions.").
    - Displays moderation case cards showing "{Post|Comment|Prayer request} by {name}", "Level 1" pill, "{date} · Reported by {reporter}", content preview, and "[N] reports · {reason}".
    - Provides 4 moderation actions per case (each records an outcome and removes the case from the queue):
      1. "Hide": hides the reported post/comment/content for everyone.
      2. "Warn author": creates an unacknowledged `Warning(reason, preview, acknowledged: false)` and sends a moderator warning notification to the author.
      3. "Keep": dismisses the reports and keeps the content visible.
      4. "Escalate to admin": moves the case to the admin moderation queue (Level 2 / backoffice).
  • What it connects to:
    - Incoming navigation: Screen 30 (`/community/:id/manage`) Reports to review card; populated by reports submitted via Screen 41 (`ReportFlow`).
    - Outgoing side-effects & routes: "Warn author" triggers `UnacknowledgedWarningGuard` and emits a notification routing the author to Screen 61 (`/warning/:id`); "Hide" updates `PostRepository` / comment / prayer visibility.
    - Guards & Repositories: `MembershipGuard` (`UserRole.superMentor`), `ReportRepository`, `ModerationRepository` (`ModerationCase`, `Warning`), `PostRepository`, `NotificationRepository`.

39. Post & comments — `/post/:id`
  • What it does:
    - Displays full post detail: header with Back button and "..." options button, tappable author row (avatar, name, role badge, "{time} · {community}"), full caption, optional photo, like & comment counts row, chronological comments list (avatar, "name · time", comment text), and a pinned bottom comment input ("Write a comment" + send button).
    - Supports optimistic likes and optimistic comment creation.
    - Automatically hides comments authored by users in the current user's blocked list.
    - Disables (without hiding) like and comment submission while offline.
  • What it connects to:
    - Incoming navigation: Tapping a post card's caption, photo, or comment button on Screen 5 (`CommunityFeedScreen` at `/community/:id/feed`) or Screen 8 (`GeneralFeedScreen` at `/general-feed`).
    - Outgoing navigation:
      • "..." button -> Screen 40 (`PostOptionsSheet` / `/post/:id/options`)
      • Author or commenter avatar/name -> Screen 43 (`/members/:id`)
      • Comment report action -> Screen 41 (`ReportFlow` with target = `comment`)
    - Repositories & Providers: `PostRepository` (`postRepositoryProvider`, `Comment` list), `ModerationRepository` (`blockedUserIdsProvider` to filter blocked users), `ConnectivityService` (`isOnlineProvider`).

40. Post options sheet — `/post/:id/options` (`BottomSheetScaffold`)
  • What it does:
    - Modal bottom sheet presenting actions for a post:
      1. "Report post" -> opens the content report flow.
      2. "Hide this post" -> hides the post from the current user's feed and shows a snackbar with an "Undo" action.
      3. "Copy link" -> copies a placeholder deep link for the post to the system clipboard and shows confirmation.
      4. "Delete post" -> (shown only if the current user is the post author) opens `ConfirmDialog` and deletes the post.
      5. "Cancel" -> closes the sheet.
  • What it connects to:
    - Incoming navigation: "..." button on `PostCard` in Screen 5 (`/community/:id/feed`), Screen 8 (`/general-feed`), or Screen 39 (`/post/:id`).
    - Outgoing navigation: "Report post" -> Screen 41 (`ReportFlow` with target = `post`).

41. Report a post (Content ReportFlow) — `ReportFlow` (target = `post` | `comment` | `prayer` | `testimony` | `user`)
  • What it does:
    - Unified, reusable reporting screen ("Report this post" / "You are reporting a post by **{name}**." / "What is wrong?").
    - Presents the 5 standard report reasons (radio/check selection) plus an optional details text area (`AppTextArea`).
    - Keeps "Send report" disabled until a reason is selected; prevents double submission and shows loading state while submitting.
  • What it connects to:
    - Incoming navigation:
      • Screen 40 (Post options sheet "Report post")
      • Screen 39 (Comment report)
      • Screen 52 (Prayer request report)
      • Screen 53 (Testimony detail "Report" button)
      • Screen 10 / 43 (User / conversation report at `/messages/:threadId/report`, refactored from Screen 11)

    - Repositories: `ReportRepository.submitReport(Report(targetType, targetId, reason, details))` which feeds into the super-mentor moderation queue on Screen 32.

42. Report sent (post) — `ReportFlow` completion state
  • What it does:
    - Confirmation screen shown immediately after submitting a content report ("Report sent" / "Thank you for helping keep the community safe. A moderator will review it.").
    - Provides two actions:
      1. "Back to community" -> pops back to the originating feed or community screen.
      2. "Hide this post" -> hides the reported post from the user's feed immediately and returns to the feed.
  • What it connects to:
    - Incoming navigation: Screen 41 (`ReportFlow` submit success).
    - Outgoing navigation: Returns to Screen 5 (`/community/:id/feed`), Screen 8 (`/general-feed`), or originating screen.
    - Repositories: `PostRepository` (hides post locally for the reporting user when "Hide this post" is tapped).

    - Outgoing navigation: "Find a member" button -> Screen 54 (`/messages/new`).

59. Error state — Applied across all 61 screens (`ErrorView`)
  • What it does:
    - Displays a consistent error screen/card when an async repository call fails or an unknown route is opened, with a "Try again" button (which invalidates/retries the failed provider) and a "Contact support" button.
  • What it connects to:
    - Connects to `ErrorView` / `ErrorScreen` (`lib/core/widgets/states/error_view.dart`), `GoRouter.errorBuilder`, and Screen 50 (`/help` when "Contact support" is tapped).

60. Account suspended — `/suspended`
  • What it does:
    - Full-screen enforcement gate that blocks access to the entire app when an admin suspends the user's account ("Your account is suspended" / "Reason: {reason}. Until {date}." / "You can read the community charter or write to the support team if you think this is a mistake.").
    - Provides two actions: "Read the charter" and "Sign out". Automatically releases when the `until` timestamp passes.
  • What it connects to:
    - Triggered by `SuspendedGuard` (first guard in `defaultGuardChain` in `lib/core/router/route_guards.dart`).
    - Outgoing navigation: "Read the charter" -> `/charter` (`CharterScreen`); "Sign out" -> `/login` (`SignInScreen`).
    - Repositories: `AuthRepository` / `ModerationRepository` (suspension state & debug scenario in `/debug`).

61. Moderator warning — `/warning/:id`
  • What it does:
    - Full-screen enforcement gate shown when a super-mentor warns the user ("A moderator sent you a warning" / "Reason: {reason}. This message was hidden:" + content preview).
    - Blocks normal app navigation until acknowledged via "I understand" (marks the warning acknowledged and continues to the app) or allows viewing rules via "Read the charter".
  • What it connects to:
    - Triggered by `UnacknowledgedWarningGuard` (second guard in `defaultGuardChain`, right after `SuspendedGuard`) or by tapping a warning notification in Screen 44 (`/notifications`); created when a super-mentor clicks "Warn author" on Screen 32 (`/community/:id/manage/reports`).
    - Outgoing navigation: "I understand" -> acknowledges warning in `ModerationRepository` and redirects to `/communities` (or original destination); "Read the charter" -> `/charter`.
