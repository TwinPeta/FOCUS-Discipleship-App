# FCU app 1.0.0 beta 4

**For testers.** The app itself is the same as beta 3: there is nothing new to learn or test. This version only moves the app to the latest back-office server, which now has a redesigned staff site.

## Install

| Phone | File | How to install |
|---|---|---|
| **Android** | `fcu.apk` | If you have 1.0.0-beta.3, the app offers this update itself (banner on Home, or **Settings > App updates**). Otherwise open the file on the phone and allow "install unknown apps" for your browser or Files app when asked. Play Protect may say the app is unrecognised: choose **Install anyway**. |
| **iPhone** | `fcu-1.0.0-beta.4-unsigned.ipa` | Install it with **AltStore** or **Sideloadly** (free, uses your own Apple ID; the app stops opening after 7 days and must be installed again). TestFlight comes once the Apple Developer account is set up. |

Check the file you downloaded against the `SHA-256` list at the bottom of this release.

## What is new

- **No change to the app.** Everything in 1.0.0 beta 3 (new icon, Settings > App updates, clearer sign-up messages) is still here and works the same.
- **Staff side (not in the app):** the back office has a new look, "Caregroups", "New members" and "Campuses" wording, local churches, and custom staff roles with editable permissions. Members do not see any of this.

## What to test

1. **Update:** on 1.0.0-beta.3, **Settings > App updates** finds this version and installs it over your current app. Your account and settings stay.
2. **Quick check:** sign in, open the Hub and a caregroup, and post. It should behave exactly as in beta 3.

## Known limits in this beta

- **Close the app and you are signed out.** The session is not saved on the phone yet.
- **You cannot change your username** after signing up.
- **iPhone:** sideloading only, so no App updates button (it explains this instead).

## For the FCU team before sending this out

- Deploy the latest API and back office first (the server changes are additive; no database migration is needed, so no `npm run db:deploy`).
- Publish from **Actions > Mobile build > Run workflow > Publish**.
