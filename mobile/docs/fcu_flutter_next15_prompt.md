- **`CommunityShell`**: the amber header used by screens 5, 6, 7, 14, 16, 18. It contains: back button (white circle 44), name panel (92% white, radius 12) with online count, messages button (white, radius 14, to `/messages`), scope switch (General | specific community), and the scrollable tab bar (Feed, Prayer, Testimonies, Pathways, Resources, Info & members; selected = w800 + 3px ink underline; auto-scroll the selected tab into view). It sits over the cover art from screen 4. **Refactor the existing feed screen onto it.** Implement the six tabs as nested routes under the shell so switching tabs keeps the header mounted (`ShellRoute`/`StatefulShellRoute`): `/community/:id/{feed,prayer,testimonies,pathways,resources,info}`.
- **`GeneralShell`**: same header without the tab bar. Name "General community", scope switch with "General" selected. If the user has no approved specific community, tapping the other segment goes to `/communities`.
- **`AmberHeaderScaffold`**: amber header with bottom corners 28, plain 44px back button, title (30/w900, height 1.05, letterSpacing -0.6), optional subtitle (16/w500), body slot, optional pinned bottom action area. Used by 9, 11, 15, 17, 19, 20 (and refactor the Hub and Profile headers onto it if they match).
- **`AppSecondaryButton`**: white, 2px ink border, radius 14, 44 or 48 high, w800. **`FilterChips`**: horizontal pills, 40 high, selected amber w800, unselected white with 1.5px `inputBorder`. **`RoleBadge`** pill (Super-mentor honey, Mentor/Student/Member cream, Campus team honey). **`PostCard`** (extract from screen 5; supports optional role badge, optional action row, optional media). **`ListRowCard`**: white, radius 16, leading tile 48 (radius 14), text block, trailing widget. **`AppTextArea`**, **`CheckRow`** (cream, radius 14, checkbox 22px), **`AvatarWithPresence`** (initials avatar with 13-14px amber dot, 2px border, when online).
- Soft style only for these screens (no hard shadows). Secondary actions use the 2px ink border button; "locked" items render at 55% opacity and are not tappable.

## 6. Quality bar
- No duplicated header, card or button code: if a widget appears twice, it lives in `core/widgets`. No magic numbers; use theme tokens.
- Every async screen: loading, empty, error. Every form: validation, disabled-until-valid actions, no double submit, loading state on the button.
- Text survives 1.3x font scale; long names ellipsize; keyboards never cover inputs; 44px minimum targets; semantic labels on icon-only buttons.
- Privacy rules from above are enforced in the data layer, not only the UI: anonymous prayers carry no author; blocked users disappear everywhere; activity and badges are private.
- Tests (keep them focused): prayer "I prayed" once-only + count; anonymous request has no author; testimony pending -> banner; pathway sequence and unlock rules; conversation send + unread clearing; report requires a reason; block hides the thread; badge rules.
