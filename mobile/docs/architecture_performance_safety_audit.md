## 1. UI/UX Arrangement, Visual Complexity & Positioning Safety

### What Is Working Well
* **Consistent Shell Architecture:** Primary screen families reuse purpose-built scaffolds ([amber_header_scaffold.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/amber_header_scaffold.dart), [onboarding_scaffold.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/onboarding_scaffold.dart), [community_shell.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/community_shell.dart), [bottom_sheet_scaffold.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/bottom_sheet_scaffold.dart)), keeping navigation chrome, padding, and hierarchy uniform.
* **Safe Area & Keyboard Handling:** `SafeArea` is applied cleanly in `26` locations across headers, shells, modal sheets, and pinned bottom bars. Notably, [AmberHeaderScaffold](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/amber_header_scaffold.dart#L48-L100) watches `MediaQuery.viewInsetsOf(context).bottom > 0`, compacting the header padding (`8/10` instead of `16/20`), hiding the subtitle, and capping the title to `1` line while the software keyboard is open so form fields remain visible on small viewports.
* **Overflow & Accessibility Discipline:**
  * `41` `TextOverflow` guards and `35` `maxLines` constraints protect dense headers, cards, tabs, and rows.
  * `0` instances of `shrinkWrap: true` in scrollable lists (avoiding nested-scroll layout bombs) and `0` deprecated `textScaleFactor` usages (`7` modern `textScaler` checks instead).
  * `72` `Semantics(...)` wrappers and `22` `ExcludeSemantics(...)` wrappers keep interactive chrome readable for TalkBack / VoiceOver.
  * Verified across `3` screen sizes (`320x568`, `390x844`, `430x932`), `3` font scales (`1.0x`, `1.3x`, `2.0x`), and a simulated `~300px` keyboard (`FakeViewPadding(bottom: 900)`) by [layout_matrix_test.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/test/layout/layout_matrix_test.dart).

### Gaps & Positioning Risks
1. **Composer Media Remove Target Slightly Undersized:** In [composer_screen.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/composer_screen.dart#L639-L649), the attachment remove button container is `40x40` px (whereas toolbar buttons above it are `48x48` at lines 559–560 and [showConfirmDialog](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/confirm_dialog.dart#L31) enforces `44x44`). Recommend `44x44` or `48x48` hit area.
2. **Hard `textScaler` Clamping vs. Accessibility:** [marquee_strip.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/landing/presentation/widgets/marquee_strip.dart), [stories_section.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/landing/presentation/widgets/stories_section.dart), and [filter_chips.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/filter_chips.dart) clamp `textScaler` to prevent clipping inside fixed-height cards/chips. Verify that clamped controls stay readable at system font scales above `1.5x` rather than shrinking relative to adjacent text.
3. **Orientation Lock:** [main.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/main.dart) locks the app to portrait (`DeviceOrientation.portraitUp`), which simplifies card positioning on phones but leaves tablet/landscape ergonomics unsupported if the app later expands to iPad/foldables.
4. **High Single-Screen Density in Composer:** [composer_screen.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/composer_screen.dart) (`656` lines) houses scope banner, community indicator, text area, max-4 attachment grid, media type switchers, and sticky bottom controls. Keep its keyboard-open viewport (`320x568` at `2.0x`) under regression whenever adding controls.

## 2. Navigation Architecture & Route Safety

### What Is Working Well
* **Deterministic Guard Chain:** [route_guards.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/router/route_guards.dart) enforces a clear priority order in `defaultGuardChain`:
  1. `SuspendedGuard` (restricts to `/suspended`, `/charter`, `/help`)
  2. `UnacknowledgedWarningGuard` (forces `/warning/:id` or `/charter`)
  3. `SignedOutGuard` (only allows public paths + `/join/...`)
  4. `OnboardingIncompleteGuard` (completes sequential `/join` -> `/join/password` -> `/join/verify` -> `/join/consent`)
  5. `MembershipGuard` (requires `approved` membership matching `:id` for `/community/:id/...`, and `superMentor` role for `/community/:id/manage`)
* **Async Loading Hold Prevents Auth Flicker:** While `session.isLoading || profile.isLoading` (or `membership.isLoading` on community routes), `runGuards` redirects to `/loading?from=...` instead of flashing protected or signed-out screens.
* **Open-Redirect Protection:** [`_backOf`](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/router/app_router.dart#L131-L136) validates `?back=` query parameters (`back.startsWith('/') && !back.startsWith('//')`) before navigating, preventing scheme-relative or external URL injection.
* **Route Order & Shell Preservation:** `/messages/new` is declared ahead of `/messages/:threadId` ([app_router.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/router/app_router.dart#L329-L337)), `placeholderRoutes` is empty ([placeholder_routes.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/router/placeholder_routes.dart#L14)), and community tabs use `StatefulShellRoute.indexedStack` ([app_router.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/router/app_router.dart#L295-L311)) so switching tabs preserves state and scroll position.
* **Deep-Link + Push Coverage:** [link_walk_test.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/test/navigation/link_walk_test.dart) validates both deep-link Back fallbacks and pushed Back pops across main and super-mentor routes.

### Gaps & Risks
1. **Inconsistent Back-Fallback Calls:** [navigation.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/router/navigation.dart) defines `popOr(context, fallback)` (`6` usages), but `20` call sites call `context.pop(...)` directly, and [OnboardingScaffold](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/onboarding_scaffold.dart#L54-L56) and [ErrorScreen](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/states/error_view.dart#L100-L101) manually re-implement `context.canPop() ? context.pop() : context.go('/')`. Standardizing every secondary back action on `popOr` eliminates the risk of a `GoError` when opening routes via deep link / push notification.
2. **Broad Router Refresh Fan-In:** [routerProvider](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/router/app_router.dart#L81-L102) listens to `8` separate providers (`authControllerProvider`, `profileControllerProvider`, `membershipProvider`, `signUpControllerProvider`, `currentRoleProvider`, `myWarningsProvider`, `pendingWarningProvider`, `suspensionProvider`) via a single `ValueNotifier<int> refresh`. While properly disposed (`release?.cancel()`, `refresh.dispose`, `router.dispose`), unrelated state emissions in warnings or profile fields re-run the entire GoRouter redirect pass.

### Memory Gaps & Risks
1. **Unbounded `OfflineCache._items` Map:** [OfflineCache](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/connectivity/offline_cache.dart#L7-L18) uses an unbounded `final Map<String, Object?> _items = {};` pinned inside a root non-`autoDispose` `Provider`. 2. **Non-`autoDispose` Family Providers Retain Scroll/Page State Forever:** While detail providers (`postDetailProvider`, `postCommentsProvider`, `threadByIdProvider`, `memberProfileProvider`, `learning_providers.dart`) use `.autoDispose`, major collection `.family` providers do **not** (e.g., [feedPostsProvider](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/providers/feed_providers.dart#L130-L133), `communityByIdProvider`, `resourcesProvider`, and family controllers for meetings, pathways, prayers, and testimonies). 4. **`FileImage` Crash Risk on Evicted Cache Files:** None of the `6` `FileImage(File(...))` usages (`sized_file_image.dart`, `initials_avatar.dart`, `post_photo_view.dart`, `composer_screen.dart:596`, `join_photo_picker.dart:78`) check `File(path).existsSync()` or supply an `Image.errorBuilder` / fallback. If Android/iOS prunes temporary `image_picker` files from cache, rendering that avatar or attachment throws a `PathNotFoundException` in the image codec stream.

## 5. Storage Management, Data Persistence & Security

### Current Architecture & Risks
1. **100% Volatile In-Memory Storage:** [pubspec.yaml](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/pubspec.yaml) includes **zero** local storage packages (no `flutter_secure_storage`, `shared_preferences`, `sqflite`, `hive`, or `path_provider`). Closing or OS-killing the app loses:
   * Signed-in `AuthSession` ([auth_providers.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/auth/presentation/providers/auth_providers.dart#L10))
   * All user-created posts, comments, prayers, testimonies, DMs, profile edits, and settings
   * All [OfflineCache](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/connectivity/offline_cache.dart) snapshots — meaning offline restarts show empty/error screens despite [OfflineBanner](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/states/offline_banner.dart#L47) claiming *"Showing saved content"*.
2. **Stale Sensitive Data Left in RAM on Account Deletion / Sign-Out:** [AccountDeletion.delete](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/settings/presentation/account_deletion.dart) invalidates `profileControllerProvider`, `membershipProvider`, and `notificationsProvider`, then signs out — **but does not clear `offlineCacheProvider`**, nor invalidate cached DM threads (`threadsProvider`), feeds (`feedPostsProvider`), or activity (`activityEventsProvider`). On shared devices or quick re-login, stale user data remains in memory.
3. **Orphaned Picked Media & Unbounded Document Attachments:** Removing an attachment in [composer_screen.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/composer_screen.dart) or cancelling a form does not delete temporary files copied by `image_picker` / `file_picker`, and `file_picker` document picks have no file-size guard before holding paths or uploading.
4. **Placeholder Password Hashing Must Not Ship:** [`fakePasswordDigest`](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/utils/password_policy.dart#L21-L32) uses iterated 64-bit FNV-1a (`salt = 'fcu-fake-salt'`). As documented in source, production auth must send credentials strictly over TLS to server-side Argon2id/bcrypt and store opaque session/refresh tokens in platform keystore/keychain via `flutter_secure_storage`.
5. **Privacy-Friendly Offline Font Bundling:** [main.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/main.dart) sets `GoogleFonts.config.allowRuntimeFetching = false` with bundled `assets/google_fonts/`, avoiding external font network requests at startup.

## 6. Loading States, Pagination & Runtime Performance

### What Is Working Well
* **Unified Skeleton & Error States:** [Skeleton](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/states/skeleton.dart) honors `MediaQuery.of(context).disableAnimations` (reduced motion accessibility) and exposes a semantic `liveRegion: true` `'Loading'` announcement. [ErrorView](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/states/error_view.dart) consistently wires retry (`ref.invalidate(...)`) and support escalation.
* **Optimistic UI with Rollback:** Likes ([FeedPostsController.toggleLike](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/providers/feed_providers.dart) / [PostDetailController.toggleLike](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/providers/post_detail_providers.dart#L32-L48)) and new posts/comments update immediately and roll back cleanly on repository failure.
* **Real-Connectivity Seam Ready:** [ConnectivityService](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/connectivity/connectivity_service.dart) abstracts online state cleanly behind a stream provider for drop-in `connectivity_plus` replacement.

### Performance & Loading Risks
1. **State Mutation Inside `ListView.builder`'s `itemBuilder`:** In [feed_list.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/widgets/feed_list.dart#L87-L92):
   ```dart
   if (i >= posts.length) {
     controller.loadMore();
     return const Padding(... CircularProgressIndicator());
   }
   ```
   Triggering `loadMore()` directly inside `itemBuilder` mixes layout/build with async controller work. While currently guarded by a `_loadingMore` boolean, if `loadMore()` errors or settles without advancing `hasMore`, every layout/scroll pass touching the spinner index repeatedly fires network/repository fetches. Move pagination to a `ScrollController` / `NotificationListener<ScrollNotification>` threshold trigger and surface a tap-to-retry footer on pagination errors.
2. **Sequential Provider Waterfalls Compound Latency:** Repositories apply `200–400ms` simulated latency per call (`96` `Future.delayed` sites across `mobile/lib`). Because feed/detail/comment builders sequentially `await ref.watch(blockedUserIdsProvider.future)` *before* calling `getPost` / `getComments` / `getPosts` (e.g., [post_detail_providers.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/providers/post_detail_providers.dart#L17-L20), [feed_providers.dart](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/features/feed/presentation/providers/feed_providers.dart#L38)), cold loads incur sequential `600–800ms+` waits instead of running `Future.wait` in parallel.
3. **Offline Recovery Doesn't Auto-Refresh Active Feeds:** Tapping `Retry` in [OfflineBanner](file:///F:/website%20backup/projects/FOCUS/FOCUS-Discipleship-App/mobile/lib/core/widgets/states/offline_banner.dart#L70) only calls `connectivityServiceProvider.check()`. If connectivity was lost on initial screen open (empty `OfflineCache`), returning online does not automatically re-fetch failed providers unless the user pulls to refresh or leaves and re-enters.
